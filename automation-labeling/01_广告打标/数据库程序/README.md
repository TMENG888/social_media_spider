# 北京臻澐口碑广告自动打标

目标库表：`social.ods_social_media_post`。目标项目严格匹配`北京臻澐项目口碑`。唯一更新列：`是否广告`。仅处理 SQL NULL、空字符串及 TRIM 后空字符串，不覆盖`是`、`否`或其他现有非空内容。

运行环境使用现有小红书 worker-01 的 mysql2 和连接函数，不修改爬虫代码，不将数据库账号密码写到文件。执行前要求设置当前进程`MYSQL_USER`、`MYSQL_PASSWORD`、`YS_LLM_API_KEY`；数据库 host/port/database 默认沿用 worker 的配置。程序限制数据库名为`social`。

## 运行

启动`start_secure.ps1`可隐藏输入 MySQL 密码并执行数据库预检，然后更新已授权范围。密码只保留在该终端进程，不保存到用户环境变量。Qwen Key 从已有`YS_LLM_API_KEY`用户环境变量读取，不发送到其他地址。

只做数据库检查：`node label_ads.mjs --inspect`。

实际处理：`node label_ads.mjs --run`。

离线基础检查：`node label_ads.mjs --self-test`，不会访问数据库或模型。

## 模型与失败处理

使用现有 Qwen 网关和`qwen3.7-flash`。起始最多16路实际 HTTP 在途，滚动240RPM与保守估算350万TPM护栏；429、网络异常或长延迟自动降并发。每条最多三次尝试，401/403停止新请求，失败保留原空值，不写入“待判断”或默认错误值。响应必须符合“是/否”JSON格式才允许更新。

广告为商业推广、交易招揽、服务获客或品牌产品宣传，不等于确认付费投放。不将原`是否广告`、广告关键词、分类、清洗标注等衍生标签给模型。只有平台、作者、标题、全文、原文章标签、图片信息和视频转写参与判断。

由于要求二分类，证据不足且未发现明确商业推广时模型返回“否”，在本地另记`evidence_insufficient=true`。这表示“现有输入未识别到广告”，不代表已证实原视频没有广告。原始内容全部缺失的行不强行分类，记入失败清单并保留数据库空值。证据引用不合格作为审计警告，不阻断已验证可用的二分类标签。

## 更新安全和恢复

先保存本批次完整目标行和已有标签快照。模型调用期间不持有数据库事务。写入前取得与小红书导入共享的短时入库锁，按主键锁定一行，再核对项目、空值和内容指纹；若爬虫已改内容或其他程序已打标，跳过该行。UPDATE只设置`是否广告`，SQL中再次限定主键、项目与空值。

每行更新前保存原值日志，提交后记成功日志。成功模型响应按输入、提示词和模型签名缓存；再次执行只查询当时仍为空的数据，可复用输入未变的模型结果，避免重复计费。不能将不存在提交日志的更新意图直接当成已提交，应以数据库读回为准。

最终重新读取项目空值数、核对本程序提交标签及已有非空标签。爬虫后续若再次覆盖此列，可能影响已完成打标；本程序不会更改爬虫行为或默认启动周期任务。
