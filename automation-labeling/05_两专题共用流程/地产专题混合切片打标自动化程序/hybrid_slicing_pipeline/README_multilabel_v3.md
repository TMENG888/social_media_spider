# 一片多标签交付 v3

入口是 `multilabel_v3.py`。`run_two_topics_test.ps1` 默认使用本版，每个专题抽样50篇，并发4。原始CSV和数据库均不修改。

## 交付结构

一行是一条语义切片，标签只存于 `标签明细` JSON数组。每个数组元素保存标签路径ID、一至五级标签、对应证据、情绪方向、打标方式及复核说明。空的四/五级标签保持null。

不再导出标签属性、标签备注、产品体系、产品系标签、阅读/播放、点赞、收藏、评论、转发、互动量、明确评价标记、正负评价标记、需求提问标记。标签路径字段不再独立占列。

`映射文章id` 是ODS文章表的内部id，不是平台的文章id。文章切片映射自身；评论优先使用显式父文章主键，辅以精确的平台+文章id、平台+文章链接校验。多匹配和关联冲突不能任选一条。评论继承父文章的热度指数和互动深度指数，没有唯一父文章或原始指数缺失时保持NULL。评论专题冲突不参与测试并计入审计。评论样本默认只选中本批文章的评论，每专题上限10条。

两个指数仅映射，不重新计算，也不是评论自身指标。做项目汇总时必须按映射文章id去重，不能把每个切片继承的指数直接相加。标签统计可临时展开JSON，主交付表仍保持一片一行。

## 匹配流程与质量边界

1. 正文非空时只使用正文；否则使用图片OCR文本。无视频ASR混用。
2. 按句段/对象做规则预切片，扫描本专题全部最新VOC标签，优先匹配标签强调方向，再补充最深层词。不只选首个或前两个命中。
3. 对部位、对象、数量单位及营销主体做门控。客户关键词本身不能证明客户需求。
4. 无强规则标签、部分事实未覆盖、客户主体不确定、混合情绪或长文本需要摘要时调用大模型补标。命中一个标签不等于整片完整覆盖。
5. API输出必须保持精确原文证据及字符偏移，标签必须存在于最新专题字典。模型与规则冲突和未保留规则命中进入人工复核，不把失败当有效空结果。
6. API失败不能静默复制长原文作为摘要。超过40字的长复制摘要会被标记复核。

规则词表和模型召回都不能保证零漏标。应对两专题和各平台做随机盲审，分别检查切片边界、标签精确率/召回率、对象归属和摘要忠实度。自动检查通过不代表人工验收通过，本版保留独立人工验收字段。

品牌组、经营主体、城市、产品档、产品系匹配状态及创新信息在本版没有权威实体映射时留空/待核验，不由检索词猜测。不要把该待核验状态视为已完成业务交付。

## 运行

在本地安全配置YS_LLM_API_KEY（不要写入代码、CSV或聊天）。API测试使用http://127.0.0.1:3000和qwen3.7-flash。运行：

```powershell
./run_two_topics_test.ps1 -PerTopic 50 -Concurrency 4 -PythonExecutable 'C:/Users/YS-Insight/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
```

仅规则回归加 `-Offline`；要测试评论另加 `-CommentsCsv '评论CSV完整路径'`。离线模式不调用API，所有候选均待复核，不能用离线结果报告模型准确率或成本。

CSV/JSON输出位于时间戳目录，含四类单元表、人工复核队列和覆盖检查。JSON留存不可变原始审计上下文，不属于精简交付表列。费用以API返回usage统计，未知usage不补零估计。输入超过32K的价格未确认时费用保持未知。
