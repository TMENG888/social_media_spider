## 新流程怎么工作

1. 保留全文 MapReduce 选出的原文范围，文章语义切片；评论始终完整一条一行。
2. 已有正常标签及文案保留，不重新逐轮审核。空标签、缺文案、原文复制、风险标签、明确口径冲突才进入定向纠错。
3. 给纠错模型一个切片、完整原文、完整标签目录、候选与相邻路径的真实定义。错标签后继续找替代标签，不因拒绝一个候选而宣布没有标签。
4. 新选标签若尚未提供其详细定义，追加真实定义检查一次；引文格式失败也只触发一次定向修复。
5. 每段证据单独保存位置。模型已经选出合法原文证据键时，程序可恢复该键对应的逐字原文，不把多个片段拼成虚假的连续引文。
6. 明确实用/套内面积不能改建筑口径，房/套总数不能直接改主卧数量；这是明确类型冲突约束，不按“正则没识别到中文尺寸”删标签。中文“十二米”“17米面宽”不会被这个约束否决。
7. 确定无适用标签才移出主表，原文与理由保留。API失败、证据不确定、撤旧标签没有理由的切片保留待审。冲突标签单独转待核，不能清掉其他有据标签。
8. 评论关联父文章、长数字ID、原文、两个继承指数均继续保留。指数没有重算，零值与空值分开。

### 审核次数

不是简单把审核次数调小：正常记录不新增语义审核；有问题的记录一次纠错，只有证据格式或新增标签定义异常时再定向检查一次。结构格式恢复与网络重试另计，不等于额外投票式语义审核。

## 运行实验

安全配置本机 User 级 `YS_LLM_API_KEY`，不要把密钥写进代码、启动参数或日志。使用 `run_replacement_v87.ps1`；默认只做冒烟，显式加 `-RunFull` 才在冒烟成功后继续同批全量。
