# v93 单片分组打标与查漏

当前入口：`run_single_unit_v93.ps1`。输入上一版完整 `delivery_results.json`，输出新的独立版本目录。原CSV、标签字典和旧Excel不改动。

1. 沿用全文语义切片结果，不重新决定边界；评论保持整条一行。
2. 每一个切片分别遍历全部适用标签组。专题一323个标签分7组，专题二580个标签分16组，每组不超过48个。每次请求只有一个待打标单元，不再按12个切片混发。
3. `source_text`只放当前切片/完整评论，附原标题及最多8条、总计1200字符的真实上下文证据，用于项目/空间指代和数值口径。上下文不是其他待打标切片，不能给当前片补外部配置、态度或数值。评论父文也只提供有限身份上下文，不借其产品事实。
4. 证据编号仍使用全文的稳定位置编号，但请求只发送当前单元和选定上下文的目录。属性证据必须在目标单元；程序在请求前拦截混入其他单元，在请求后核对真实位置。
5. 定义核验按同一个单元的候选标签分批，每批最多12项；替代补选只处理一个单元，使用紧凑全目录找替代，再核验真实定义。高风险定向复核和恢复摘要/做法也只处理一个单元。替代阶段的路径目录不等于一次喂全部标签详细规则。
6. 保留有据旧标签；新标签核验后追加并按ID去重。旧标签只有两项审核一致明确不支持才撤回。上一版的明确语义否决作为历史冲突，不允许无理由重新加回。
7. 同一个共享API运行器限制全局实际并发≤10。可安全续跑检查点；失败/结构错误和费用显式保留。不要把本地环境变量密钥打印或写入参数。
8. 模型补选和对象证据检查之后，自动执行 [v95联合关键词补标](README_joint_keyword_supplement_v95.md)，含原v94原文规则。逐片把原文和已有标签视为一个候选查找整体，冻结已有标签；对象可由有据旧标签提示，新增属性必须在本片原文里。同对象且必要条件满足直接追加；否定、提问、跨对象、数值口径和历史争议转待核。仅标签文字出现属性时记录为不补标，不当成漏标待核。新补标签不参与同轮继续推导。不改变切片，不删除原标签，没有新增API用量。
9. 导出产品/观点两张Excel，保留标签字典、强调方向、文章评论源关联、统计、人工审核、查漏记录和费用。新增请求方式和每请求待打标单元数，便于验证确实执行了单片策略；关键词方法、命中字眼与证据追加到已有补标审计页。

最终交付前还会检查明确的对象冲突：住宅样板间风格不能直接填会所风格，会所面积不能直接填景观面积，仅出现“住宅”不能直接填别墅。这些检查仅把新候选送待核，不猜测替代标签、不覆盖旧标签、不丢弃原文。入口会保留失败检查点并复用成功请求缓存，自动补跑一次技术失败；语义争议不靠重跑投票解决。补跑后仍有请求结构或API失败时，交付闸门不通过。

费用只汇总本轮输出目录里每次真实请求的usage，包括冒烟、失败和重试；读取缓存不重复计费，历史v92及Codex对话用量不包含在内。输入Token已包含缓存Token，总Token按输入加输出计算。费用依照既有程序费率估算，不代表网关账单；缺usage或缺适用价格要单列。

```powershell
.\run_single_unit_v93.ps1 -InputResult '上版目录\delivery_results.json' -OutputDir '新的单片版目录'
```

只重新导出完成结果时加 `-ExportOnly`。该入口会运行离线回归、实际请求隔离检查、同批对照和保存后Excel核验；不会因为标签变多就声称准确率提高。仍需人工金标准验收，不能承诺零漏标。

回退时使用原v92目录；`full_dictionary_supplement_v92.py --request-mode batched`仍保留旧请求方式。不要把单片结果覆盖旧交付。
