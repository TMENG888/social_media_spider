# v92 全字典补选

本轮的交付入口为 `run_label_supplement_v92.ps1`。原 MapReduce/H 主流程保留，用它生成的兼容 `delivery_results.json` 作为输入，增加本文描述的后置查漏流程。回退时继续使用旧目录，不能覆盖原CSV、字典或旧交付。

## 处理流程

1. 保留原全文语义切片边界；一条评论完整一行。把主表、待核及历史排除的原文范围全部列入检查。已有标签、理由、摘要非空也不能跳过。
2. 按专题读取完整适用字典：专题一323条、专题二580条。每组最多48条，分组收到完整原文、全部相关单元和该组的完整标签路径、强调方向、真实打标说明，不以关键词裁掉标签。
3. 程序为原文生成证据编号。模型选择编号，不负责抄写引文；程序取回原文并校验属性证据属于目标单元。句段目录只定位证据，不决定切片边界。
4. 新候选、已有疑似错标及历史冲突候选送统一定义核验。核验实际对象、属性、口径、模态和真实引文。数值提示只提请检查，不自动选择面积标签。
5. 错候选、不确定事实继续在完整标签目录里寻找替代标签，再读取替代标签的真实定义核验一次。同一被明确语义否决的标签不能在替代轮无理由加回；历史冲突须解释旧必要条件。
6. 只追加确认标签到原八键JSON，片内同一标签ID只保留一份。不同项目或户型的不同事实不因标签相同而删除。错标只有查漏和定义核验均确认不支持才单独撤回，不删其他合法标签。
   对新增的高风险路径（客户本人关注点、对象数量、价格口径、空间对象等）核对其具体必要条件，只做一次定向复核。存在定义争议则转待核；明确不支持时继续一次全目录替代查找，不反复投票。此闸门已经集成核心 `process()`，不会用关键词自动删除标签。`recheck_new_label_risks_v92.py`仅用于把同一闸门应用到已完成扫描的本批结果，复用成功扫描，不重跑193来源。
7. 可能把客厅尺度借给餐厅、把景观风格当外立面、把公共公园面积当社区景观等情况进入待核。规则不限制阿拉伯数字，中文尺寸可以有据支持；不确定触发器不直接删除旧标签。
8. 历史无标签范围发现合法事实时，用原边界恢复单元，生成并核验做法或摘要。不能生成忠实文案则保留待核，不能用空JSON、空摘要伪装完整交付。
9. 导出两个Excel，保留各自字典页、“标签强调方向”、原文和来源关联、人工审核、补选覆盖、补选纠错、未解决事实与本轮费用。字典遍历完成、候选审理完成和人工验收分别记录。

## 限制

全字典遍历是流程覆盖，不代表模型逐项判断全部正确。标签数量不能代替准确率；字典缺项、证据不足、模型冲突和API/合同错误分别保留。不能承诺绝对零漏标，正式统计仍需要独立人工金标准验收。
