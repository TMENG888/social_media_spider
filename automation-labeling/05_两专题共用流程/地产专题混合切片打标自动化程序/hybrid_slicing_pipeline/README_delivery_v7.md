# v7 全文切片与全字典分支审核

当前入口为 `run_delivery_v7.ps1`，不是历史的v6启动器。

## 处理顺序

1. 模型读取完整文章主体和全部适用标签，生成语义单元。一片多标签，评论整条一行。
2. 程序按标签分支将全部字典分为每批不超过40项的审核任务。每批仍读取完整原文，独立判断每项标签是否有证据，不受首轮候选约束。专题一323项、专题二580项均进入审核。
3. 程序检查分区是否完整、是否有矛盾；有问题时修复并逐项裁决，不将未审核项偷偷视为不支持。
4. 模型根据全部审核证据进行最终语义综合。同一对象可以合并切片，但不能以“避免碎片化”为理由删除有依据的细标签。综合遗失标签必须逐项说明定义或证据不支持的原因；剩余遗漏另做裁决，只有证据位于合法单元内才允许回填。
5. 模型选择固定字典编号，程序回填八键标签JSON，不按模糊名称猜测。程序检查原文定位、对象/尺寸错配、文案复制及标签合法性；歧义保留在人工审核队列。

评论映射文章id为评论源表的平台文章id；父文章ODS主键保存在追溯记录。父文章可提供项目上下文和两个指数，但不得替评论生成态度或继承父文章的事实标签。主体优先级为文章内容、文章视频内容、已有图片OCR文本。

## 验证、成本与限制

`python -m unittest test_delivery_v4 test_delivery_v5 test_delivery_v6 test_delivery_v7 test_multilabel_v2 test_multilabel_v3 test_user_examples_v51 -q` 运行离线回归。

`evaluate_delivery_v6.py --result <目录>/delivery_results.json` 检查已知漏标/错标的事实锚点；`verify_delivery_v4.py` 检查交付合同。锚点通过不代表全量准确率，也不保证零漏标。最终仍需人工对不同平台、长短文章、评论建立独立金标准，计算召回率和精确率。

分支审核明显增加调用次数和输入Token；费用分生成、分支审核、修复、综合及裁决记录。仅已知输入不超过32K的价格档可估算；超过该档或usage缺失的费用保持未知，不填零。API估算不代替网关账单。

单元置信度与全部适用检查满足阈值且无冲突才机器自动通过；自动通过不等于人工核实，也不等于已经测得90%准确率。审核队列保留具体原因，完整分支响应保存在JSON，Excel只展示紧凑追溯摘要。
