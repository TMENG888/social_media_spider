# 全文归属补全与停止条件

当前批量入口 `run_bulk_v96.ps1` 在原四阶段之后调用 `apply_identity_completion_v97.py`。
新增 `stages/05_identity_v97`，保留原01至04检查点及签名；不会为了补身份重跑成功切片或标签。
手动只补既有生成结果：

```powershell
python apply_identity_completion_v97.py --output-dir '明确的原生成目录' --taxonomy '当前VOC字典.xlsx'
```

补全器 `identity_completion_v97.py` 与已保存工作簿的补标使用同一套规则。

1. 阅读完整主体、标题及末尾身份信息，逐片确认实际对象。连续户型、园林、精装介绍可承接案名，不要求每片重复名称。
2. 身份与标签/摘要证据隔离：身份可来自片外，配置、数值、观点不能随身份迁移。原文、切片边界、标签及摘要不变。
3. 品牌、经营主体、项目分别决策。明确集团简称可按显式别名归一，金茂对应中国金茂；保利、中海、招商不能用品牌名任选分支主体。项目法律公司不等于集团主体。
4. 观点项目名称及角色允许多对象。字典外真实住宅保留原样名称并标非研究项目，不伪造研究ID。混合研究内外对象时ID数组无法代表全体，ID留空并记录原因。
5. 产品单值项目遇多个实际对象不能任挑一个；保留多对象原因与证据，供后续边界改进，不擅自改切片。
6. 评论整条一行，父文身份和评论话题关系分开取证。仅挂在父文下、泛聊或无法区分父文多个对象不能继承。
7. 每个非空候选验证字典、源键、逐字证据和身份联合一致性；独立审核实际对象、住宅属性、完整对象集合与冲突。
8. 空值也独立反查全文。审核发现实际有证据遗漏时，提出带源键修正并再裁决，不通过反复采样把置信度刷高。
9. 停止原因分为来源不足、主体分支不唯一、多对象单值限制、字典外、不适用、别名未核实、身份冲突。请求失败和审核分歧单列，绝不冒充“应该留空”。

`identity_summary_v97.json`、逐来源trace和工作簿补充证据保留每项依据及未补原因。机器复核不等于人工金标准，也不承诺零漏补。
本阶段HTTP仍受共享并发、滚动TPM/RPM预算及软停控制。缓存命中不重复计费，失败/重试的已知usage保留，未知usage或不适用价格不按零元计算。
原CSV、输入表、成功来源检查点和历史工作簿均不覆盖。

离线回归：`python -m unittest -v test_identity_completion_v97`。

## 项目与经营主体关系补核（独立模块，尚待接入默认流程）

`identity_relation_index_v97.py` 只从有原文证据的主体决定和实际住宅对象集合提取候选。
候选不等于开发关系。`identity_relation_review_v97.py` 另做两次原文关系审核，区分住宅开发经营与物业、施工、设备供应及联合主体。
来源全文hash、原文位置、原始案名及具体集团主体均保留。跨来源线索还须同城明确证据，短名、音近、同名跨城和冲突关系不得直接套用。
即使关系已核验，也只是提供给目标切片的同对象审核，不能自动根据检索词或品牌名写入。

目前仅模块实现和离线回归通过；没有把这些新关系候选当成已补入单元，也未修改当前运行中的补全器。
关系安全回归：`python -m unittest -v test_identity_relation_index_v97 test_identity_relation_review_v97`。
