# v6 全文切片与全字典覆盖审核

## 针对三类漏标的修改

1. 首轮遗漏：生成时输入完整主体及全部适用标签。另一次独立请求重新读取全文和全部字典，审核并返回完整纠正单元，不受首轮候选限制。所有字典选择编号分成“支持、不支持、歧义”三个互斥分区；缺编号、分区交叉或支持标签与单元不一致会阻止自动验收。分区枚举本身不等于已经证明零漏标。
2. 名称回填失败：程序给每个适用字典标签颁发固定选择编号，例如D0165。模型只选编号，程序从当前字典回填八键标签JSON。旧名称兼容仅允许唯一规范名称/唯一末级名称，不做模糊猜测。专题二“容积率”同时可能对应土地或产品定义，不能擅自任选，必须由模型根据具体定义选固定编号。
3. 程序误删：取消任意的同句/相邻句对象限制，支持同一连续上下文中的会所配置。按逗号等分句过滤营销邀请，不连带删除邻近实际配置。保留明确反例保护：整套面积不是餐厅尺度，主卧不是次卧，邻近高速不是入口，验资提问不是本人预算，销售宣传不是客户阶段/成交。证据不确定时保留待审，不自动通过。

一片多标签、文章全文输入、评论完整一行、来源优先级、八键字典JSON、评论源表平台文章ID映射、父文章指数继承及原文证据追溯均保持。

v6.1另记录独立审核的标签增删。任何从全文结果中消失的首轮标签须在removed_draft_labels逐项解释；缺理由不得自动通过。不直接把首轮和审核标签取并集，避免把已经纠正的错标重新加入。纠错理由是追溯依据，不是正确性证明。

## 运行

在此文件夹执行 `powershell -NoProfile -File .\run_delivery_v6.ps1 -SmokeOnly -SkipExcel` 先跑6个真实API冒烟源；去掉SmokeOnly完成同一基线80篇文章、120条评论。冒烟需同时通过处理结构/覆盖分区及已知漏标、错标事实锚点，否则不启动全批。全局并发最大10；生成和审核使用同一限流器；原API地址与qwen3.7-flash保持不变。

密钥读取进程环境变量YS_LLM_API_KEY；不存在时启动器提供隐藏输入，仅在进程内使用，不保存到代码、检查点或结果。不要将密钥写入命令历史或聊天。认证失败停止，瞬时错误最多重试两次。原文件、数据库和历史结果不修改，结果保存到独立时间版本目录。

已完成检查点复用，失败请求保存usage并可续跑。首轮与覆盖审核分阶段记录token、耗时和估算费用；输入超过已知32K价格档或usage缺失时费用保持未知，不用零冒充。该方案一般每个源两次逻辑请求，比单次模型自检增加成本。

## 评估与限制

`python -m unittest test_delivery_v4 test_delivery_v5 test_delivery_v6 -q` 执行合同与已知规则反例回归。

`python evaluate_delivery_v6.py --offline-output test_results_v6_offline` 重放旧响应，只证明程序回填/过滤规则的变化，不可能补回模型首轮从未选择的标签。

`python evaluate_delivery_v6.py --result <结果目录>/delivery_results.json` 逐条比较已知正反事实锚点；标签数量增加不等于正确率提高。还需人工对跨平台、长短文章及评论建立独立金标准，评估最终召回率及精确率。模型置信度和自动通过不是实测准确率。

导出包括产品、观点、人工审核队列、来源追溯、渠道覆盖、费用、全字典覆盖审计和已知问题锚点对比。没有真实API结果前不得宣称首轮遗漏已修复。离线结果全部保持待审。
