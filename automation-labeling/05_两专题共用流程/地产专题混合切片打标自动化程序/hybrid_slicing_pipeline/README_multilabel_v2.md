# 多标签版本（2026-10-08）

`run_two_topics_test.ps1`默认运行`multilabel_v2.py`。旧流程用`-LegacySingleLabel`保留。
源CSV、ODS数据库、历史Excel均不改动。密钥只从`YS_LLM_API_KEY`读取，不写入代码。

流程：正文非空则用正文，否则用图片OCR；原文不清洗或改写；按句末分上下文窗口；
扫描最新VOC字典召回64个候选；模型先切片再给每个切片多个标签；程序验证
原文位置、专题字典、对象和证据、摘要及情绪；零有效标签的切片扩大至128个候选再试一次。
合法空结果接受，API失败/格式错误不能复活候选；候选召回不是完整性保证。

输出JSON及产品/观点多标签CSV。一行一个语义切片，`labels`是完整标签对象数组，
各自含一级至五级、证据、情绪及机器检查状态。`start`/`end`为原文Unicode字符索引，
end不含，不能当作UTF-8字节或JavaScript UTF-16索引。

`04_需复核单元.csv`含全部尚未人工验收的切片。所有`human_status`初始化为待人工验收，
`count_in_statistics`为0。另有JSON文档级异常可定位API失败、空输出和无可用正文，
不能因为CSV无切片就忽略文档级异常。不得将机器证据通过冒充人工验收。

已实现保守的对象硬否定，不是通用语义蕴含证明；项目先提取原文提及，品牌、经营主体、
城市等尚不自动推断，`project_status`保持字典待核验。必须另接经业务确认的项目字典。
摘要20至80字为目标，不为补足20字编造。超80字不静默截断；产品与观点共用摘要校验。
数字校验和营销主体校验不能证明摘要全语义正确，仍须人工验收。
