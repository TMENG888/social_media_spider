# MapReduce切片打标

入口为 `run_delivery_v11.ps1`（当前调用 `delivery_v76.py`）。原API地址、模型、全局并发10保持不变。密钥从进程或本机用户环境变量读取，不写入程序和结果。

1. 主体优先级：文章内容→文章视频内容→已有OCR；选首个非空字段，不拼接。评论保持完整。
2. Map：专题一323标签、专题二580标签，按一级分支及二级/三级邻近顺序分批，每批最多48标签。每批读取相同全文和本批全部定义，不先按关键词删候选。检查全部字典键并输出对象、事实证据及切片建议。
3. Reduce：阅读全文及Map提议，按连续对象语义决定最终分区。同一对象连续讲述多配置合为一片；不同项目、房间、独立设施不因同标签或文字重叠合并。每个字符在完整分区中出现一次，排除的区间也保留追溯。
4. 定位：起点必须原样存在。唯一原文引文的出现次数可程序纠正；模糊位置必须经模型对真实位置候选确认，不能自动近似截断。
5. 整合：按原文证据范围把所有Map标签提议送入对应最终片，标签去重。一片多标签，不复制一片多行。跨边界的粗证据分别核验，不能直接当成两边都成立。
6. 逐标签核验对象、属性、模态与定义。随后独立转写具体产品做法/观点摘要，校验项目、态度和重复事实，程序只从最新字典回填八键标签JSON。
7. 未完成Map、未定位、证据不足、低置信度等记录保留具体问题，不能冒充标签已完整覆盖。API检查点只复用完整相同请求，所有阶段共用全局并发限制。

评论映射文章id当前使用评论CSV原始文章id；父文章ODS主键另存来源追溯。评论指数继承唯一关联父文章，缺失不转为0。父文章只能辅助评论指代，不能迁移文章配置作为评论标签证据。

运行：`./run_delivery_v11.ps1 -SampleFile ./test_results_v10_random_20261009_api/fresh_sample.json -OutputDir ./独立新目录`

前后质量对比使用 `compare_mapreduce_v76.py`。参考锚点未经人类签核，不能把局部锚点命中率称为全样本准确率；仍需人工审核。MapReduce重复输入全文，费用未必低于单次全字典请求。
