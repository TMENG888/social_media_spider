v11.25完整随机批已返回24篇文章及36条评论，共131单元、325标签。格式、关联和字典回填检查无错误，但真实来源回归仍发现重复层高、两条空评论摘要、昵称职业推断、广告误作本人关注等错误，且2条来源处理不完整、全部单元需人工审核；该批仅作对照，未作为最终已验收交付。

v11.26已接入以下修复，正在对同一抽样内7条问题来源真实回归；范围不会缩成7条，之后仍需完成24+36当前版本结果并独立验收：

- 独立文案核验分别使用PROSE/SRC原文键，程序附逐字发言者，避免摘要序号、原文证据序号、子评论序号混淆。普通和聚焦摘要修复两条路径均检查未经正文支持的职业身份。
- 完整客户路径定义优先于同名末级词。“精装交付”“四居洋房”不自动支持客户本人精装、户型或物业形态关注；真实判断与提问无需必须出现“我”。有争议时独立复核，不改字典或硬配替代标签。
- 重复审核增加详略混淆核查。同一验房总数与分项可为同事件重述，但不同缺陷、不同状态或仅部分重叠不删除整个标签。
- 相邻边界使用左右实际原文绑定的不透明键；缺项只补无效/遗漏键，保留已有有效决定。完整但语义串联冲突仍须重新审核，程序不按关键词或数段落自动决定边界。

上述离线协议及生产集成测试证明接线和失败保护，不证明真实切片、标签选择已经准确。当前暂无最终两表工作簿。

1. 全文输入模型选择语义边界。评论不切分，完整原文与已有回复一行。初稿、最终粒度修正和连续主题核验都由模型判断；关键词不决定边界。
2. 最终逐个相邻边界判断保留/合并，程序按完整边界决定组成连续分组，不让模型编排可能重号、漏号的groups。连续户型参数与解释、同主题甲乙项目对比可保持整体；教育、交通、商业等独立主题仍分开。合并必须同一具体主题、无跨片、无有关/无关混入；传递合并不同主题会失败并有界重审。
3. 合并后重新审核全部适用标签分支，不继承旧切片的标签或摘要。最终标签必须通过定义、对象、数值、逐字证据核查，八键由最新VOC字典回填。大平层不当大高，园林/室内描述不转为外立面，第三方客群定位不当本人关注。
4. 评论摘要与情绪仅用当前完整评论，不借父文事实。失败摘要最多执行一次核心说法选择、必要的一次选择协议恢复、重新生成及独立核验；证据键不是子评论序号。发言者从原文标题承接，不推职业，不把一个人的话归给另一人。不可靠结果仍留空待核，留空不算修复成功。
5. 文章身份承接选择程序提供的实际原文身份键，不要求模型计数同一名称的第几次出现。未知、后文才出现或冲突身份不强补；某片身份失败不再给其他所有片追加该片错误。
6. 原文双项目污染标题不能改成“甲与乙共同配置”。每日频率分母、项目/房间对象、数值、规划与已实施状态都需证据。字幕/音频乱码不凭常识补具体材料名。指标仍原值继承、不重算，评论映射文章id仍是评论源表文章id，ODS父主键另存追溯。
7. 重复事实核验区分同标签不同事实与同事件的综述/详情；记者转述与业主原始具体证据不因叙述形式变化就重复计标签。已解决的分支引文问题移入历史审计，协议缺项及真实语义矛盾不能隐藏。

当前流程包含多次生成、全字典分支核验、局部证据与文案核验，不是每篇仅一次API请求。Token和费用须按所有实际阶段汇总；成功请求缓存可复用，未知usage/价格不计为零。合法ID、机器置信度、离线测试通过不能证明精确率/召回率；目前尚无全样本人工金标准。

本轮样本固定为种子20261009的24篇文章及全部36条关联评论，排除此前已处理的文章，不替换难样本。v11.21及v11.25完整对照、v11.22～v11.24局部真实回归已观察到实质错误；v11.26正在重点回归，完整60来源仍待验证。最终两表工作簿尚未导出和完成保存后核验，不应作为正式已验收交付。

## 历史修复记录

v11.14在相邻合并之后增加最终逐片粒度核验，单元素大切片也可重新拆分。模型读取完整原文选择全部起点，程序检查无损覆盖、逐片审核索引及声称拆分/合并是否实际改变边界；评论不进入此步骤。四面宽不补具体房间朝向，单项目豪宅不扩大为板块档次，房屋层高不自动转为土地规划条件。数字引文切断黏连数值时，数值类标签待核，不猜分隔，也不因此剥夺不依赖该数值的洋房形态标签。评论直接点名项目不再要求父文重复同一引文；隐含指代仍须父文消歧，昵称不作项目证据。社区服务机构不推成卫生服务中心，历史居住不推成当前居住，室内外听感差不推外立面构造。评论摘要保留不同发言者与争议，不补未查看视频的声音事实。价格关注按字典定义反查，不额外要求购买意向。

截至本次修正，v11.13的60条随机来源已完成但存在实读确认的语义错误；v11.14尚待真实API回归和最终工作簿验收。离线测试或合法ID不证明修正已在真实输出奏效。

v11.15针对v11.14真实回归的失败响应增加一次粒度协议恢复：原文片头仅取短引文，出现序号不是单元序号；每片必须给具体主题类型，mixed必须有实际新增边界。规则不替模型按关键词切片，失败仍保留无损原文及人工审核原因。采集确认字典保持原文件不变，程序补充P01北京臻澐的有据简称“臻澐”，记录补充来源并拒绝简称碰撞。v11.14价格关注已实测恢复，但不能据此宣称粒度和项目字段也已修复；v11.15仍在真实回归中。

v11.16在全局粒度响应未落实拆分时追加一次有界恢复：仍输入完整文章，但只让模型重新确定失败目标区间中的实际语义起点；程序无损回填，不按关键词或长度切片，也不跨区间借文本。全局失败响应和局部成功审计分开保存，不能把失败全局计划标为已通过。探盘推广标题即使点名项目也不自动证明个人购房关注；该身份标签进入待核，不影响已核实的项目名。

文章按文章内容、文章视频内容、已有图片OCR文本选择首个有效主体。模型读取完整主体，以完整对象/主题转换选择边界；程序回填原文，不按关键词、字数或标签数决定最终边界。评论整条一行，保留已有回复。

每片审核完整适用标签字典分支，再独立核验定义与证据。待定候选也进入二核，但不直接变成正式标签。引文格式失败时模型选择原文证据编号，程序原样回填。所有输出标签由字典回填八个键，一片多标签，不按标签复制切片。

v11.5对独立审核的缺失/重复决定按标签键补审。补审仍失败只将缺项标为待核，不清空其他合法且逐字有据的标签；部分协议未完成的单元不能自动通过。“其他标签已覆盖”理由会送独立核验，不直接作为支持。重复事实核验采用各切片自己的证据编号，不能跨片套引文；只归并已确认同对象同事实的标签，不删除切片原文。行业惯例推断的房间朝向、主卫窗套主卧窗等进入定义裁决，不凭高置信度自动认可。

v11.7起对字典附加条件的拒绝做独立反查，禁止将例子变成必需监测数值。列表格式序号不当作新增测量值，真实尺寸仍核验。重复标签每次仅比较A/B两个切片，不让模型选择全局单元编号；不同显式对象标题阻止跨对象归并。只有同对象、同事实、逐字证据和数字置信度均通过才移除重复标签，否则保留待核。

v11.11增加最终对象证据保护：主卫窗不转为主卧窗、房间尺寸不转为整套面宽、衣帽间空间不直接证明衣柜配置、LDKB/宽厅不直接证明横厅、豪装不直接证明质量。支持理由仍依赖行业惯例推断时，标签不进入正式JSON，保留完整原文及待核原因；不自动填入替代标签。保护规则只是发现已知类型错配，不能证明所有语义错误均被覆盖。

v11.12要求相邻多片合并必须明确确认same_object与same_topic，并给出具体object_scope及object_description。same_project/project_overview不在允许范围；同项目户型、交通、医疗、教育、商业等独立主题不能整体合并。同一户型配置、同一会所设施和同一具体方案仍保持完整，不能为每个标签拆行。全文粒度复核也明确要求把上一主题收尾句留在上一片。合并协议未通过时保留无损原分区并复核，不用关键词或字数补猜边界。另外家政间数量必须有明确计数，空间存在本身不补数量一。

当前v11.13对“模型判断同一事实但漏一侧证据编号”的A/B响应做一次独立补核。两侧必须均有有效逐字证据才能执行归并；补核失败保持待核，不凭高置信度或文字理由直接删除。补核与普通生成共用全局并发10，费用和请求均进入审计。

观望和规划提问保留为相关内容；相应原文出现时给全字典分支审核增加正反例，避免必须复述“客户阶段”“我关注”等标签文字才支持。休闲设施关注不能扩大成地段位置关注，规划提问不能改写成已批准或已建成。关键词仅触发复核提示，不决定切片边界或直接授予标签。

拟排除内容必须反向确认没有专题相关事实；专题二观点不需要一定包含产品配置。营销词不能删除同句配置。摘要/做法必须转写，不添身份、因果或配置；无法可靠完成时留空并注明人工审核。

评论的映射文章id使用评论源表的文章id；父文章ODS主键在追溯中保留。两个指数继承原文章，空值与零区分。多项目对比文章保留对齐数组；单项目文章保持原标量格式。评论仍使用数组。缺少项目证据不能强行填满。

运行示例：

```powershell
powershell -NoProfile -File .\run_delivery_v11.ps1 -SampleFile .\test_results_v10_random_20261009_api\fresh_sample.json -OutputDir .\test_results_v11_new -SmokeFirst
```

`-SmokeFirst`只用于包含本次固定关键案例的测试样本；自定义新样本不要添加该开关。样本文件须包含documents与sampling，正文及评论来自只读CSV。重复运行保留缓存并跳过同版本完成来源；代码或字典变化会重新组装，但相同成功请求可复用。

CSV/JSON及追溯、审核队列保存在独立目录。Excel仅导出产品信息单元、观点信息单元。人工审核原因在备注，验收状态紧接其后。机器验收、合法标签ID、关键锚点通过均不是全量准确率证明；空标签不能全部认定为漏标。必须对原文核查对象、事实与标签定义，相同标签不一定是重复事实。不同签名版本的documents不能直接全部汇总；使用delivery_results.json或当前签名快照。费用含多个核验阶段，未知usage/价格仍报告未知，不当作零成本。
