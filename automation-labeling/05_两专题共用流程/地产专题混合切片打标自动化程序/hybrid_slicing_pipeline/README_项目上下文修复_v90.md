# 项目归属补全闸门

`project_context_v90.process`已接入当前`completeness_v89.process`的标签与文案处理之后；不会重新切片，不改变标签明细、摘要、产品做法、指标或评论文章映射。单独恢复已有交付数据用`run_project_context_v90.ps1`，输入权威`delivery_results.json`，输出必须为新版本目录。旧默认核心没有被替换。

1. 程序从完整主体、独立文章标题、评论父文及父文标题定位真实项目字典别名，产生带原文位置的身份编号目录。采集关键词、话题标签及专题字段不是身份来源。
2. 只对项目漏填单元调用模型。模型阅读全文并判断单元是否仍在讲同一对象，只选择已有身份编号。程序回填真实ID、名称、角色和原文证据，不允许模型编造项目ID或拼接引文。
3. 文章可用前文、后文或标题确认同一项目；对象切换、外地同名楼盘及行业泛谈不沿用。评论必须明确点名或有据关联父文同一项目话题，不能因父文章已经映射就直接继承。
4. 决策及各项目关系置信度至少0.90，身份引文和原文位置通过程序检查才补齐。低分、未知编号或API失败保持空值并说明具体原因，不反复提高置信度。完全没有真实项目身份编号时，输出合同禁止known。
5. 八个研究项目的ID、名称、角色统一为位置对应JSON数组。已有明确候选外案名及null编码不强行改为研究项目，也不丢掉原有案名。
6. 所有阶段使用同一ApiRunner，并发最多10、120秒硬超时、瞬时错误最多重试2次，认证失败停止。成功请求和来源检查点复用；费用汇总包含未通过语义冒烟的探索请求，未知usage不视为零费用。

先以臻澐504户型、安澜北京规划价格、熙瑞园林三个来源的11个漏填作冒烟门槛，再修复同批其余异常。回归检查源批次、切片边界、八键标签、原文定位、文案、完整评论、长ID及指数完全保留。补齐项目不代表既有标签均正确，也不代表人工验收通过。

交付沿用现有两份Excel和八页结构，项目归属的判断、引文和位置放在“源记录与文章关联”页的“本轮项目归属核查”列；其他未完成标签问题继续留在“未完成待核”。
