# 断点恢复入库：数据库字段校验修复

日志触发位置：common/src/import-mysql.mjs 的 verifyTable。
旧导入校验要求数据库字段名称、数量、物理顺序全部相同，而预检只检查可访问性和权限，两者不一致。
INSERT/UPDATE 已显式指定字段名，物理顺序不同以及可选新增字段不会影响对应赋值，不应阻断恢复。

## 本次改动

- common/src/import-mysql.mjs：按必需字段名称校验，不要求物理顺序相同。允许有默认值、可空、自增及生成列等可省略的额外字段。
- common/src/run-worker.mjs：预检复用同一校验；权限检查也使用实际要写入的字段清单。
- 真正缺少字段、存在无默认值的额外必填字段或试图直接写入生成列时，输出具体诊断并停止。

更新时先安全停止节点，把更新包内容覆盖到含 common 和 worker-02 的部署根目录，再重新启动。
保持 tasks、.state、runs、浏览器登录和凭据文件。无需重置 Redis 或删除断点。
重新启动后会再次恢复本地帖子和评论，并按文章ID/平台/项目及评论ID等原有键更新或插入。
旧记录不是重新生成一份，作者统计保护与分类NULL逻辑保持不变。

## 验证边界

生产源码已通过语法检查；帖子表和评论表各6项模拟结构测试通过。

若真实结构缺少必需字段，新预检会报告明确字段名，不能以跳过验证代替修复。
