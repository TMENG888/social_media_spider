小红书 Playwright RPA：五机 Redis 动态任务分配版（2026-10-01）

【跨机器分发】
1. 不要通过网络共享直接拖拽整个小红书文件夹，这种方式可能因NTFS/共享权限造成部分工具文件漏拷。
2. 在源机器双击“生成可分发包.bat”，只使用release-packages目录中生成的单一ZIP文件。不要通过网络共享直接复制正在运行的“小红书”目录；其中worker的.state可能含模型缓存符号链接，Windows资源管理器会报0x800705B7，且复制登录态和本机断点会污染新节点。
   正确步骤：先把ZIP复制到目标机器本地磁盘，再右键“全部解压”；不要在网络共享内直接运行，也不要逐项跳过复制错误。
3. 目标机器先将ZIP复制到本机磁盘，再解压到一个全新目录；不要覆盖已经报权限错误的旧目录。
4. 解压后双击“验证部署完整性.bat”，只有显示Deployment verification passed才可启动worker。
5. ASR依赖缺失时会首次启动自动安装；也可手工双击common\安装ASR依赖.bat。部署包已内置common\runtime\asr-models\faster-whisper-small离线模型，视频识别不再运行时连接Hugging Face。
一、分发与首次启动
1. 每台机器复制同一版本的 common 文件夹和本机对应的 worker-01 至 worker-05 文件夹，两者必须同级。
   common 包含源码、Redis 客户端依赖、Node 和浏览器。不要仅发 worker 文件夹。
   ASR 还需要各机可用的 Python 及 requirements-asr.txt 所列依赖；若提供 common/runtime/python/python.exe 则优先使用，否则使用本机Python。启动预检会在打开浏览器前实际加载离线模型；依赖、模型文件或模型兼容性异常时不会开始采集。
   不要把其他机器的 runs、.state、浏览器登录态、密码或 .update-backups 一起分发。
2. 五台机器使用相同的 Redis 地址、库号、campaign 和 common/tasks/redis-tasks.json。
   当前已配置为 redis://127.0.0.1:6379/0，ACL 用户名 xhs_worker，campaign=xhs-2026-year-v2；五台机器必须能访问该内网地址。建议在路由器中为Redis主机绑定固定DHCP地址，避免重启后地址变化。
   Redis 服务运行在本机独立 Docker 容器 xhs-redis，不与公众号的 wechat-redis 共用实例；6380端口仅允许 Private 网络的 LocalSubnet 访问。
   URL 中禁止放用户名或密码。也可不填 URL，启动时交互输入。
   MySQL密码仍为每次隐藏输入且仅存在当前进程环境。Redis密码首次隐藏输入后，会保存为各worker独立的.state\redis-password.dpapi；内容由Windows DPAPI绑定当前机器和当前Windows用户加密，之后启动该worker会自动读取，不再重复询问，也不会写入BAT、JSON、日志或分发ZIP。
   新Redis密码必须先通过实际连接及AUTH/PING验证才保存；认证失败保留原凭据。启动时也先验证已保存的Redis密码，若被拒绝则提示隐藏输入当前密码，验证通过后更新；认证或连接仍失败时不会进入MySQL输入和采集阶段。
   worker-01至worker-03提供“保存或更新Redis密码.bat”和“清除已保存Redis密码.bat”。三台目标机器分别运行一次保存脚本即可；加密文件不能跨机器或跨Windows用户复制使用。Redis密码变更、保存时输错或更换Windows用户后，重新运行保存脚本覆盖即可。Redis 工作节点密码由服务端管理员通过 C:\ProgramData\XhsRedis\显示工作节点连接信息.bat 查看并安全分发。
3. 双击“启动工作节点.bat”。默认是 Redis 模式，连接失败不会偷偷退回本地分片。
   启动先检查运行环境，再连接 Redis/校验清单，验证 MySQL 连接、表结构与 INSERT/UPDATE 权限，最后打开浏览器。
   首次访问小红书由用户登录，后续关键词共用本机浏览器/会话。出现验证码或频控会停止该节点，需人工处理；不绕过平台限制。
   生产入口默认启用周期监督器：每轮随机运行45至60分钟，安全归还未完成任务后随机休眠30至60分钟，再自动从Redis继续领取；直到全局任务完成。
4. 工作节点仅保留生产启动、安全停止、环境检查、本地备用分片和凭据维护入口；测试启动文件及测试任务配置已移出生产目录。
   “启动本地分片_备用.bat”使用原五份固定任务分片。不要同时运行本地分片与Redis生产任务。
5. 打包时自动检查Windows PowerShell脚本语法及worker测试文件残留；开发测试目录和旧版重复源码不随生产包分发。

二、任务池与进度
全量清单共331个专题关键词任务：专题一223个、专题二108个。来源是原五份任务清单，未增加、删除或重复分派检索词。
所有节点连接一个小红书独立池，按原需求表顺序发布并领取：先专题一的223词，再专题二的108词；前五词为“中海 住宅、中海地产 住宅、中国海外发展 住宅、中海企业发展 住宅、中海宏洋 住宅”。快的机器会做更多任务，不再每台固定67或65词。多机并发只能保证领取顺序，不能保证耗时不同的关键词也按相同顺序完成。
单个热门关键词仍由一台机器串行完成，不会把同一关键词的翻页拆给五机。
任务标识包含专题、关键词、cutoff。发布幂等；同ID不同内容拒绝发布。
实际池名 = campaign + mysql/export + 清单哈希；导出测试绝不会确认正式入库任务。
每个关键词成功采集且完成入库后才确认完成，然后自动领取下一个关键词。
重复启动同一个 campaign/清单不会重采 Redis 已确认完成的任务。
本次从本地分片首次切换 Redis，不自动把旧本地任务的 completed 导入 Redis；会重新核验，MySQL 按业务键幂等入库。
任务列表或有效采集参数改变会产生新的清单哈希。五机必须一起更新；否则是不同任务池，可能重复采集。
需要开启下一轮增量/重新扫描时，五机统一修改 campaign，如 xhs-2026-year-v2；旧池保留，不自动清空。
实时日志显示全局待领取/执行中/已完成/重试耗尽数量和本机当前词。
.state/redis_queue_status.json 是最近一次全局状态快照（含失败任务），并非实时数据库。

三、租约、安全停止和恢复
默认300秒租约，30秒心跳，10秒命令超时；使用 Redis 服务器时间判定所有权。
单次心跳连接失败会在本地安全租约窗口内每5秒显式重连，不会把短暂网络抖动立即误判为失租；只有服务端明确拒绝旧token、认证/权限失败，或Redis持续不可用直至安全窗口耗尽时才安全停机。停机后禁止旧节点入库或确认任务，本地SQLite与导出文件保留，任务待服务恢复和租约到期后重新领取。
领取/续租/完成/失败/回收使用 Lua 原子操作，同一时刻一个任务仅有一个有效 token。
掉线或强退后任务会在租约到期后由在线节点回收；失败最多尝试3次，默认60秒、120秒退避。
重试耗尽的任务保留 failed 状态及原因，不伪报完成。排查后可用新 campaign 重跑；不会自动无限重试。
安全停止：双击本机“安全停止当前任务.bat”，完成当前笔记并保存、导出和允许的尾批入库，再归还未完成任务。
安全停止同时终止周期监督器；在休眠阶段双击也会在最多5秒内结束等待，不会自动启动下一轮。
每轮休眠前关闭本轮浏览器进程，登录资料和ASR缓存保留；下一轮重新启动浏览器并复用登录态。MySQL密码只在监督器进程内保留，关闭窗口后失效；Redis密码使用本机当前Windows用户的DPAPI密文保存，下次启动自动读取。
采集失败但已由Redis原子放回有限重试队列，只记为“失败尝试/等待重试”，不会再把本周期误判为异常；限时安全停止并归还任务后进程正常退出，监督器会进入30至60分钟休眠并自动重启。只有Redis确认失败、租约丢失、数据库/采集器未处理错误或全局重试耗尽才会阻止自动重启。
若出现 login_required、risk_controlled、import_failed、租约异常、Redis重试耗尽或无法读取进度，监督器立即停止，不会反复重启。
不要直接关闭窗口；安全停止会让当前视频完成、asr_job持久化并收尾后台识别。Redis 失联或租约失效后禁止旧节点继续提交，数据仍留本地。
原子确认失败但数据已入库时，关键词可能被重新领取。这是“至少一次”调度，不是跨 Redis/MySQL 的 exactly-once 事务。
MySQL 原有业务键去重及命名锁用于重放兜底；Redis 确认与 MySQL 提交并不是一个分布式事务。
同机恢复继续用本机 SQLite；另一台机器接手会重新搜索该关键词，无法自动读取离线机器的 SQLite/ASR 缓存。
旧节点断网期间未入库数据仅保留在该机，不能宣称全部自动跨机迁移。请保留原机 runs/.state 以备恢复。
每台机器一个 worker，worker.lock 防止本机重复启动。不要运行中覆盖源码或共享浏览器配置目录。

四、采集业务规则（保持不变）
专题一：文章=采集；评论=不采集；项目=全国地产设计产品力监测。
专题二：文章=采集；评论=采集；项目=北京臻澐项目口碑。
两份需求表均未规定“分类”字段固定值，因此文章和评论的分类保持为空；不得用专题名称自行概括填充。
最新排序必须核验选中状态。边加载、边逐篇核验详情日期，只保存2026年且不早于2026-01-01的文章。
年度模式没有20或300次滚动上限；最近8篇不同笔记的详情日期均非2026年才触发年度边界。
未知日期/详情失败会打断观察窗口，不能当作旧帖凑满8篇。
连续15轮无新增则记录 platform_no_growth，代表平台当前可见结果结束，不保证取得全平台全部帖子。
评论不额外按评论日期过滤，只采目标文章当前可见评论；现有评论滚动上限仍适用，不保证历史全部评论。
每篇立即提交SQLite，默认每20篇增量入库，关键词结束处理尾批与最终幂等入库，无人工审核门槛。
图文/视频均支持；原简介与标签分开，标签英文逗号分隔，图片描述字段留待后续大模型处理。
视频先提取网页字幕；没有字幕时，详情线程只保存基础文章、媒体地址并写入SQLite asr_job，随后继续采集下一篇。后台队列将MP4/M4A等媒体持久化到断点目录，复用常驻Faster-Whisper进程识别，成功后只更新当前文章断点并通过MySQL upsert回填“文章视频内容”。
ASR质量恢复参考视频号实现：依次执行VAD主识别、无VAD补识别、30秒重叠分块恢复及开头8秒复核；同时检查文本密度、循环重复、提示词回声及常见Whisper幻觉。字幕始终清洗为单段逗号文本，不编造字幕。
每条视频拥有独立asr_job状态和最多3次尝试。进程中断后downloading/running自动恢复为retry_pending并复用已完整下载的媒体；下载中断留下的.part文件会在精准重试前安全重建。失败只重试该视频，不重跑整个关键词；耗尽后进入dead_letter并保留真实错误，基础文章仍可正常入库，文章视频内容保持NULL且绝不填入伪字幕。无口播、无音轨、空音轨或静音视频按无口播完成，不会反复识别。
文本去emoji；视频文本换行转逗号。文章获取时间、评论获取时间使用北京时间。

五、目录与运行环境
common/tasks/redis-tasks.json：签名校验的全量任务清单，不直接手工改。源码manifest模块可从原五队列重新生成。
worker-xx/tasks/task-queue.json：保留的本地备用分片和worker路径配置。
worker-xx/.state/redis/<池名>/专题/关键词/checkpoint.sqlite：本机Redis采集断点。
同一checkpoint.sqlite中的asr_job：视频媒体、识别尝试、转写审计、重试与死信状态；媒体临时保存在同目录asr-media，成功后默认删除，失败时保留供精准重试。
worker-xx/runs/redis/<池名>/专题/关键词/：采集结果、collector_status、task_status及入库报告。
worker-xx/runs/worker_status.json：本机本轮执行记录，Redis完成状态以服务端为准。
common/src/redis-task-queue.mjs：原子队列；redis-dispatcher.mjs：心跳/派发；lease-guard.mjs：入库租约保护。
测试用Redis服务程序不随生产包分发。需自备五机可连接的Redis服务，建议受支持版本、TLS或可信内网、防火墙白名单、持久化AOF与noeviction。
Redis账号应仅授权小红书 xhs:* 命名空间及此程序所需命令：PING/EVAL/TIME、HASH/ZSET读写等（Lua也受ACL检查）。
不可把Redis无鉴权暴露到公网，也不要给客户端账号FLUSHALL/FLUSHDB权限。
