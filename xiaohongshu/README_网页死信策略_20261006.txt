小红书单篇网页不可浏览：死信策略（2026-10-06）

明确显示“当前笔记暂时无法浏览”的单篇帖子：
1. SQLite note_dead_letter 持久化关键词、帖子 ID、原链接、原因与北京时间。
2. candidate 标记 dead_letter，不伪造文章、评论或字幕，不算非今年帖子。
3. 前两篇出现该提示：点击提示内真实关闭按钮，核验原搜索页恢复，再继续下一篇。
4. 连续第三篇出现该提示：第三篇也写死信，停止本节点，不点击第四篇；收尾保全已完成数据。
5. 正常详情解析成功会清零该连续计数；年度日期规则不变。
6. 本机后续启动默认跳过已有死信，另行精准补采时需显式恢复对应记录。

死信保存在各机器本地断点库，导出到对应任务 runs 目录的 note_dead_letters.jsonl。
run_summary.json、collector_status.json 和 worker_status.json 会展示死信数量与完整性标记。
任务可在处理完可访问结果后结束，但 has_dead_letters 明确表示仍有待补采，不等于全量无缺漏。
本地死信不会自动变成 Redis 全局帖子黑名单，其他机器处理同一关键词时仍可能再次遇到该篇。

安全验证、登录限制、租约失效仍立即停止，不等待三次。
无法关闭提示或无法恢复正确搜索页，也立即停止，避免采到首页推荐。
连续三篇停止时沿用 web_unavailable 状态：Redis 当前未完成关键词释放回待领取，周期自动重启暂停。

验证：调用生产 processNote 的四组受控浏览器/SQLite 回归通过。
测试没有主动制造真实平台限制，没有连接 MySQL 或重置 Redis。
