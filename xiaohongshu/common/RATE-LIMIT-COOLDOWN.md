# 访问频繁后的安全冷却

仅明确的“300013 + 访问频繁/操作频繁/访问频率过快”进入自动冷却：
第一次 2 小时、第二次 4 小时、第三次停止并等待人工检查。时间到后只允许正常采集续跑，不保证平台一定解除限制。
验证码、滑块、登录失效、其他安全限制不会按定时冷却自动恢复。Redis 不可用、租约异常也不自动恢复。

现有节点默认共享整个小红书生产任务池的冷却（保守地一起暂停，并非自动识别账号）。
必须同步更新所有机器；未更新的旧节点不会遵守门禁。所有节点配置的 rateLimitCooldown.group 必须相同。
独立账号若确需分组，需人工配置；同一任务池的不同组仍共享任务，但冷却不再联动，请谨慎。

冷却存储在 Redis 的 xhs:{任务池}:rate-limit-cooldown:shared 哈希，
本机 .state/rate-limit-cooldown.json 是只读镜像。重启不清空冷却。正在运行的同组节点最多约 10 秒发现冷却，
发出安全停止信号并收尾当前工作，归还未完成任务；冷却等待期间不访问平台、不占任务租约。
多个节点在同一冷却期报限频只计一次；采集器和父进程重复报告同一运行也只计一次。
次数不会随正常周期或启动清零；第三次和人工限制必须人工确认后解锁。

使用原启动 BAT，默认周期模式会在冷却到期后自动续跑。SingleCycle/单轮模式仍只跑一轮：
会遵守启动前冷却，但本轮遇到限制后不自动启动第二轮。
安全停止 BAT 可在冷却期间取消后续续跑。再次人为启动是新的启动请求，但仍受 Redis 冷却约束。
退出码 76 表示已确认的共享冷却；77 表示人工检查；5 为租约异常。其他错误不擅自重启。

人工确认浏览恢复正常后，可在 PowerShell 执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\common\reset-rate-limit-cooldown.ps1" -WorkerRoot ".\worker-01"
```

需键入 RESET 二次确认。该命令只清理共享冷却，保留审计和事件去重记录，
不重置采集任务、不删数据库/本地断点、不启动采集。恢复前先检查同组其他节点。

更新后需安全停止并重新启动节点才能完整生效；不会热修改已运行的旧进程。
