# 百度资讯 Playwright RPA

该项目以百度资讯为发现入口，先沉淀文章链接，再按最终域名选择解析器，将详情页映射到 `ods_social_media_post` 的32个字段。默认关键词为“中国海外集团 住宅”，日期范围从2026-01-01到每次运行当天；配置文件不固定结束日期，后续运行会自动包含新增文章。

## 最简单的使用方式

双击 `启动百度资讯爬虫.bat`，可选择：单个检索词、导入 XLSX/JSON/TXT 任务文件批量采集、对历史输出目录断点续爬，或修复旧版爬虫已经写入的哈希ID。采集结束后再输入MySQL用户名和隐藏密码；密码只存在于当前进程内存，不写入BAT、配置文件或日志。默认数据库为 `127.0.0.1:3306/social`，表为 `ods_social_media_post`。

数据库建表SQL中的 `id` 不是 `AUTO_INCREMENT`。本项目因此在入库事务中锁定并读取小于 `1000000000000000` 的有效最大ID，新文章依次使用 `MAX(id)+1`；数据库已存在的同链接文章沿用原ID并更新内容。旧版项目生成的15—16位URL哈希ID只有在它与当前文章URL重新计算出的旧哈希完全一致时才会迁移，不会误改其他来源的高位ID。入库完成后，数据库实际分配的ID会回写到本地JSONL和同名CSV。

入库事务会与数据库中本年度文章进行正文去重。标题只作为辅助信息，不再单独触发拦截，避免“标题相同、正文不同”的文章被误删。程序先判断规范化正文是否完全一致，再将清洗后正文做4字符片段切分，以Dice系数计算字符相似度；正文完全一致或相似度达到50%，且文章链接不同，才跳过入库。因此“标题不同、正文相同”仍能识别为重复。同一链接继续执行幂等更新，便于正文清洗规则升级后刷新旧记录；同一批次中新插入的文章会立即加入比较集合，避免批次内部重复。结果写入 `database_dedupe.jsonl`，并显示在爬虫任务表的“入库去重”工作表及“数据库状态”列。

互动类数值字段统一执行空值归零：文章点赞数、文章收藏数、文章评论数、作者粉丝数、作者点赞数和文章分享数。文章视频时长允许为空。该规则同时应用于新采集记录和入库前读取的历史JSONL；已有非空数值保持不变。

如需修复日志中已经入库的两条异常ID，重新双击BAT选择菜单4，输入原运行目录中的 `ods_social_media_post.jsonl`：

```text
runs/<run-id>/ods_social_media_post.jsonl
```

批量模式可使用项目根目录的 `百度资讯_检索词任务表.xlsx`、`keywords_template.json` 或每行一个词的 TXT 文件。Excel 程序只执行“渠道=百度资讯”“是否启用≠否”“执行状态≠已完成”的行；JSON 同样支持 `enabled/status`。日期、每批条数、最大页数和最大文章数都可以按检索词覆盖。

最简单的 JSON 可以直接写成 `[{"keyword":"中海 住宅"},{"keyword":"保利 住宅"}]`，也可以写成字符串数组 `["中海 住宅","保利 住宅"]`。推荐使用 `keywords_template.json` 的对象结构并给每个词配置稳定的 `id`，以后调整列表顺序也不会改变检索词任务ID。

每次运行都会生成 `爬虫任务表.xlsx`：

- `任务汇总`：按检索词显示发现、成功、失败、字段不完整和终止原因。
- `爬虫任务`：每个发现链接一行，包含平台、解析器、尝试次数、失败原因、ODS及数据库状态。
- `失败待重试`：只保留失败、字段不完整、日期未知和待抓取链接，作为断点续爬核查清单。
- `入库去重`：记录被正文完全一致或正文相似度规则拦截的文章，以及命中的数据库文章ID、标题、链接和相似度。

## 资讯页面资格过滤

入库前会过滤明显的非资讯页面。房天下采用“页面类型过滤”而不是整个平台封禁：`newhouse.fang.com`、`esf.fang.com`、`zu.fang.com` 的楼盘/房源页，以及正文同时出现多项“楼盘详情、主力户型、项目地址、预售证、一房一价、房价走势、贷款计算器”等产品页特征时，任务状态记为“非资讯排除”，不会进入ODS，也不会进入失败重试。`news.fang.com` 等真正的房天下资讯文章仍允许采集。

## 文章正文清洗

正文优先从平台实际文章容器提取，不再默认使用整页最大文本。已配置百家号、界面新闻、北青网、中国日报网、中国经济时报、凤凰网、人民网、红网、东方财富、上观新闻、房天下资讯、央广网、证券之星、长江日报、中国网、三秦网、同花顺、大众网、智通财经、中金在线、新华网、挖贝网、中国经济网、财经网和钛媒体等平台。正文容器提取后，再按平台删除推荐阅读、评论、客户端下载、版权页脚、导航、广告和分享按钮等内容；正文段落、文中小标题、记者署名和必要的图片说明仍保留。

百家号使用独立清洗规则：ODS“文章标题”字段单独保留标题，正文会删除重复标题、作者/官方账号、发布时间、发布地区、AI导读区块及百度页脚，正文从来源标注或首个正文段落开始；点赞/点踩等页面组件图标不会写入文章图片链接。

若已配置平台没有找到正文容器，程序会把文章标记为“字段不完整”，而不是把导航栏或页脚误当正文入库。`crawl_audit.jsonl`及新生成的爬虫任务表会记录清洗前长度、清洗后长度和清洗规则版本，便于抽查清洗是否过度。

ODS“文章标签”固定写入 `null`，不再读取网页 keywords、栏目名或标题。断点续爬会识别旧清洗版本并重新抓取；旧版脏记录不会因历史状态为“成功”而被直接沿用。

## 百度安全验证自动恢复

程序不会破解或自动操作验证码。识别到“百度安全验证”、异常请求、HTTP 403 或 429 后，会离开验证页并自动休眠2～5分钟，再重试原URL，默认最多2轮。详情页重试耗尽时，该文章写入失败断点并继续下一篇；百度列表页重试耗尽时，当前检索词保留断点并结束，但批量任务会先入库已落盘文章，额外休眠1～3分钟后继续下一个检索词，不需要人工恢复。

冷却参数可通过 `config.json` 的 `maxSecurityRetries`、`securityCooldownMs` 调整，也可使用命令行参数 `--max-security-retries`、`--security-cooldown-min-ms`、`--security-cooldown-max-ms`。同一公网出口下不要同时启动多个同编号工作节点；5台设备若共用一个公网IP，仍可能比不同公网出口更容易触发安全验证。

分布式工作节点采用保守限速：启动后立即执行，每篇文章间隔6～12秒，每页列表间隔8～15秒，检索词之间间隔20～60秒。连续3个检索词触发安全验证时，全局熔断休眠30～60分钟后再继续后面的任务。限速只能降低触发概率并等待限制解除，不保证网站一定恢复，也不使用浏览器指纹伪造、自动验证码、代理轮换或隐藏自动化特征。

断点续爬时选择菜单3，输入与上次相同的 XLSX/JSON/TXT 任务文件和上次输出目录。程序每处理完一篇文章就持久化 ODS 与任务审计；恢复时保留已成功及已判定超出日期范围的链接，只重试失败、字段不完整和日期未知任务，并继续发现尚未出现的新链接。ODS 在单关键词目录及批量合并时都按“文章链接”幂等覆盖/去重，MySQL 入库也优先按“文章链接”更新已有记录，因此重复运行不会重复插入同一链接。

## 运行

要求 Node.js 20+、Microsoft Edge 或 Chrome。百度资讯在部分环境下不会向无界面浏览器渲染结果，因此默认采用可见浏览器窗口运行。首次进入项目目录后执行：

```powershell
npm install
Copy-Item config.example.json config.json
npm run crawl
```

只发现链接、不打开详情页：

```powershell
npm run discover -- --query "中国海外集团 住宅" --max-pages 3
```

按每批10条采集（默认设置）：

```powershell
npm run crawl -- --query "中国海外集团 住宅" --start-date 2026-01-01 --batch-size 10 --max-pages 20 --max-items 200
```

批量执行关键词文件；以下命令测试本次3个规划类关键词：

```powershell
npm run batch -- --keywords keywords_planning_test.txt --batch-size 10 --max-pages 20 --max-items 200 --start-date 2026-01-01 --force
```

批量结果按关键词保存在 `batch-data/` 子目录；根目录同时生成去重后的 `combined_ods_social_media_post.csv/jsonl` 和 `batch_summary.json`。同一文章命中多个关键词时只保留一条记录，并只保留首次发现该文章的一个检索词；后续重复命中不会再向“关键词”字段追加内容。

输出位于 `data/`：

- `discovered_links.csv/jsonl`：百度资讯发现的原始链接、标题、来源、卡片日期和排名。
- `ods_social_media_post.csv/jsonl`：详情页发布日期通过2026时间窗口校验后的ODS记录。
- `crawl_audit.jsonl`：每个链接的最终URL、解析器、日期判定、正文长度和失败原因。
- `run_summary.json`：发现、处理、入库候选数量和停机原因。

仓库中的 `sample-data/` 是2026-09-12完成的首屏10条实测：发现10条、处理10条，5条通过2026-01-01至2026-09-12的详情页日期校验。其余记录包括2条过期、2条日期无法确认和1条页面超时；这些记录保留在审计文件中，没有伪造日期或写入ODS。

## 专题一批量测试结果（2026-09-12）

`keywords.txt` 中7个关键词共发现65条、逐条处理65条；各关键词共有37次合格命中，按文章链接去重并合并关键词后得到35条ODS记录。所有合并记录均有标题和正文、日期位于2026-01-01至2026-09-12，且32个ODS字段齐全。结果位于 `batch-data/`。

## 解析器扩展

`src/parsers/registry.mjs` 按最终域名选择解析器；已为百家号、澎湃新闻和网易配置专用覆盖逻辑，证券之星、中金在线、美通社、界面、观点、央广、新华等先使用JSON-LD/OpenGraph/正文容器通用解析器。

新增平台时复制 `src/parsers/TEMPLATE.mjs`，填写标题、正文、时间和作者选择器，然后在注册表中加入域名规则。专用解析失败时仍保留通用解析结果。

## 时间过滤

百度卡片日期只用于审计。最终是否进入ODS，以详情页的结构化时间、`time`元素或正文完整日期为准。无法确认完整年份的记录标记为 `unknown`，不会写入ODS；早于2026-01-01或晚于运行日的记录标记为 `out_of_window`。

列表使用百度资讯的时间排序。程序每次发现最多10个新链接，立即逐一解析这一批的详情页；整批完成后，只要其中至少一篇的详情页日期早于2026-01-01，就把该关键词标记为 `older_than_start_date_found` 并停止翻下一页。未知日期、未来日期、单篇解析失败不会误触发正常结束。遇到验证码、HTTP 403或429则作为异常立即停止。

输出JSONL和CSV严格使用SQL表的32个字段及其固定顺序。当前明确把“文章图片信息”设为 `null`；“文章视频内容、文章标注、分类、清洗标注、地点、是否广告、广告关键词”等需要后续模型或业务处理的字段暂存为 `null`。“项目”默认写入“全国地产设计产品力监测”；JSON检索词任务文件可在根节点或单条任务中设置 `projectName`，例如专题二使用“北京臻澐项目口碑”。“文章获取时间”统一按北京时间（Asia/Shanghai）生成。“文章图片链接”仍保留页面能够直接提取的原始图片URL。

数据库去重按“项目”隔离：同一URL、平台文章ID或相似正文在同一项目内去重；同一文章若同时属于两个专题，可在两个项目下各保留一条，专题二不会覆盖专题一的“项目”字段。

## 批量关键词复用流程

1. 复制一份关键词文本文件，例如 `keywords_general_test.txt`。每行只写一个关键词，不要使用表格符号或逗号。
2. 保持百度资讯按时间排序参数 `rtt=4`。程序每批获取最多10条结果，并依次打开详情页。
3. 批内所有详情处理完后，若发现任一文章早于2026-01-01，该关键词正常结束；否则继续下一页。
4. 新关键词建议使用新的 `--state-dir` 和 `--output-dir`，防止与历史浏览器会话及结果混用。
5. 运行完成后先查看 `爬虫任务表.xlsx`，处理“失败”“字段不完整”“日期待复核”和“待抓取”记录；补充平台解析器后可断点续爬。
6. 验收通过后，使用 `combined_ods_social_media_post.jsonl` 执行MySQL结构校验及入库。

本次10个通用关键词的运行示例：

```powershell
npm run batch -- --keywords keywords_general_test.txt --batch-size 10 --max-pages 20 --max-items 200 --start-date 2026-01-01 --output-dir general-test-data --state-dir .state/general-test --force
```

日后新增关键词时，只需修改关键词文件和输出目录名称，采集脚本、字段映射、日期终止逻辑及任务表生成逻辑均可直接复用。

也可以使用一键脚本。它会自动创建带时间戳的新输出目录和独立状态目录：

```powershell
.\run-keywords.ps1 -KeywordsFile keywords_general_test.txt
```

需要覆盖同名输出中的历史关键词结果时使用：

```powershell
.\run-keywords.ps1 -KeywordsFile keywords.txt -OutputDir production-batch -Force
```

## 开发任务表

单关键词与批量执行结束后都会生成 `爬虫任务表.xlsx`，包含：

- `任务汇总`：各关键词发现数、成功数、失败数、字段不完整、日期待复核和结束原因。
- `失败待重试`：平台、链接、详情日期、百度卡片日期、解析器、失败原因和尝试次数。
- `爬虫任务`：所有发现文章，便于从检索词追溯到链接、最终平台、ODS及数据库状态。

该Excel仅用于开发验收，不属于 `ods_social_media_post` 入库数据。

## MySQL入库

默认目标是 `127.0.0.1:3306`、数据库 `social`、表 `ods_social_media_post`。入库脚本会先读取数据库实际字段，并与32字段名称和顺序严格比对；一致后才在事务中使用参数化语句写入，主键重复时更新该行。

交互输入用户名和密码（密码不会显示，也不会写入磁盘）：

```powershell
npm run import:mysql -- --input batch-data/combined_ods_social_media_post.jsonl
```

也可以仅在当前PowerShell会话设置环境变量后运行：

```powershell
$env:MYSQL_USER = "你的用户名"
$env:MYSQL_PASSWORD = Read-Host "MySQL密码" -AsSecureString | ConvertFrom-SecureString -AsPlainText
npm run import:mysql -- --input batch-data/combined_ods_social_media_post.jsonl
Remove-Item Env:MYSQL_PASSWORD
```

若云数据库要求TLS，可额外设置 `$env:MYSQL_SSL = "true"`。在没有用户名和密码时，程序不会尝试连接或写入数据库。

只校验待入库文件的字段结构、不连接数据库：

```powershell
npm run import:mysql -- --input batch-data/combined_ods_social_media_post.jsonl --validate-only
```

## 合规的反爬稳定策略

- 单浏览器、单详情页串行处理，不并发轰炸站点。
- 列表页默认随机等待3–6秒，详情页默认等待4–8秒。
- 网络错误最多重试2次，并递增等待时间。
- 使用持久化浏览器目录保存正常会话和Cookie，支持断点续爬。
- 保存链接去重集合、运行审计和断点文件，避免重复请求。
- 遇到HTTP 403、429、验证码、安全验证或“访问过于频繁”立即停止并记录原因。
- 不提供验证码破解、代理池轮换、浏览器指纹伪装或访问权限绕过。
- 默认拦截字体和视频资源，降低带宽；图片请求不拦截，以便部分懒加载页面保留图片地址。

实际批量运行前，应确认目标网站条款、robots政策及内容使用授权。搜索结果页只负责发现，入库链接必须使用详情页规范链接。
