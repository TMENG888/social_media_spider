# 爬虫运维面板

这里保存当前运维面板的前端、Python 服务端、远程状态读取、受校验操作和离线测试。页面按小红书、抖音展示 work01—work04，包括机器活动、登录验证、关键词进度、入库库存、发布日期和平台限制记录。所有时间使用北京时间。

## 配置和启动

需要 Windows、Python 3.11+、Node.js 22.13+、OpenSSH，以及已配置的采集部署目录。Redis、MySQL、SMB、SSH 权限沿用部署环境；本目录不附带密码、私钥、登录态或生产机器配置。

```powershell
python -m pip install -r requirements.txt
Copy-Item config.example.json config.json
# 修改 config.json 后启动
./launch.ps1
# 或隐藏启动
./start.ps1
```

`config.json` 中的 `package_root` 指向已有部署包，目录包含“小红书/common”“抖音/common”及各 worker；`monitor_root` 指向已配置的独立 `feishu-monitor`。仓库英文平台目录不能直接代替原部署树。相对路径按配置文件所在目录解析；输出和临时目录默认放 E 盘。`machines` 填写实际计算机名、共享根目录、SSH 别名、启动目录和各平台 worker，不能照用示例机器名。DNS 不可用时，可在对应机器增加 `address`。

启动前在当前进程提供 `MONITOR_XHS_PASSWORD`、`MONITOR_DY_PASSWORD`、`MYSQL_USER`、`MYSQL_PASSWORD` 等部署所需环境变量，或由自己的凭据加载器设置；不把密码写入 Git。MySQL 地址沿用采集脚本的环境配置。原机 DPAPI 文件及凭据加载器不随源码发布。Node 依赖使用目标部署平台 `common/node_modules` 中的 mysql2。

默认只监听 `127.0.0.1:54176`。已有局域网部署可填写 `listen_host=0.0.0.0` 和本机 `lan_address`，并由管理员配置对应专用网络防火墙规则。发布脚本不更改防火墙，不自动安装计划任务。

## 页面和操作

- 后台每 300 秒重新采样，手动更新只读取状态。机器状态结合心跳、原进程状态和真实采集活动判断；没有观测到流水时显示未确认。
- 帖子流水使用已提交且回读核验的事件，并按事件 ID 去重；评论库存净增与采集流水分别展示。首次启动没有库存历史，需积累后才能比较增量。
- 日期按平台、项目和关键词读取；最早保存或入库日期不表示连续覆盖到该日，最新保存帖子的日期也不是单向推进的年度进度。
- 登录面板显示原会话二维码和短信挑战，可刷新允许刷新的二维码、获取或重发短信并提交验证码。滑块、点选、刷脸由人工在原机器完成；短信和手机确认阶段不会自动刷新二维码。
- 恢复采集仅开放小红书固定入口。执行前核验控制通道、停止保护、安全冷却、运行锁、机器身份和既有计划任务。SSH 不可达或核验不通过时返回具体拒绝状态，不把指令发出当作恢复成功。
- 操作校验 Host、Origin、CSRF、白名单及幂等标识。登录会话失效或已有未处理指令时拒绝覆盖。短信仅在内存中转换为原桥接协议密文，不写入面板日志。
