# 视频号云 MySQL 入库待机重试

版本：`channels-mysql-standby-20261023-v1`

## 行为

- 入库仍先做 3 次短重试，间隔 5、10 秒。
- 随后仅对 DNS、连接超时、断网、连接重置等网络错误进入待机，默认窗口 30 分钟；依次等待 30、60、120 秒，之后保持 120 秒间隔。
- 窗口从短重试耗尽时开始，包含后续连接/入库尝试耗时；截止后不启动下一次尝试。已经进行中的数据库操作不被强杀，因此整个退出耗时可能超过窗口。
- 每次仅运行入库程序，连接已关闭后才等待；不重新打开视频、不重新采集，不因失败跳到下一个关键词。网络恢复且入库回执确认成功后，原流程继续。
- Redis 任务子进程保持存活，既有父调度器继续续租。Redis 租约丢失或安全停止写入该节点的 `.state\stop.requested` 后，等待阶段约 1 秒内响应，不清除停止标记。已开始的数据库操作先完成并确认提交结果，不强杀 COMMIT。
- 待机耗尽仍保留本地 SQLite、导出、失败回执，进入既有基础设施暂停流程；不伪造成功，不自动确认 Redis 任务。

只在入库程序明确返回 `retrySafe=true` 且 `commitState=not_attempted` 时才允许重试。密码错误、表结构错误、磁盘满不进入网络待机；数据库锁和死锁仅保留原来的短重试。提交结果为 `unknown` / `committed` 时禁止自动重放，仍需核对数据库。

## 入口与范围

普通采集收尾、启动时的旧断点恢复、ASR 补采入库共用上述逻辑。旧断点恢复失败不会再经异常出口重复开启一次完整待机；ASR 入库失败也会停止后续关键词。

维护入口 `recover-pending-import.ps1` 的父进程有 600 秒超时，因此它显式设置 **5 分钟**待机，给导出及收尾留出时间；原有外层超时和提交核对保护仍有效。

本次未修改启动前独立 MySQL 预检、数量只读回查及 Redis 自身的重试策略；也不改变采集完成标准、Redis 任务状态、表结构或凭据。

## 配置

正常入口默认启用，无需修改配置。支持在启动进程的环境中设置 `CHANNELS_MYSQL_STANDBY_MINUTES`，范围 0–120 分钟，0 关闭长待机（仍保留短重试）。命令行 `--standby-minutes` 优先于环境变量，维护入口固定传入 5。

入库封装器还支持 `--stop-file <文件绝对路径>`。各 PowerShell 入口已显式传入对应节点的停止文件；单独调用时也可从 `WECHAT_WORKER_ROOT` 推导。不得跨机器复用停止文件路径。

## 识别日志

| 事件 | 含义 |
| --- | --- |
| `mysql_import_standby_started` | 开始网络待机，包含版本和最大窗口 |
| `mysql_import_standby_wait` | 下一次重连间隔、剩余窗口和安全错误码 |
| `mysql_import_standby_recovered` | 入库进程已成功，继续原流程 |
| `mysql_import_standby_exhausted` | 窗口耗尽，保留本地数据并停止 |
| `mysql_import_wait_cancelled` | 检测到安全停止或退出信号，不再发起入库 |
| `mysql_import_commit_reconciliation_required` | 旧提交结果不明，禁止自动重放 |

等待期间最新 MySQL 回执保留最后一次实际失败的事实，不写入虚假的成功回执。`worker-recovery.ps1` 现在保留结构化错误码、提交状态，不再将它们简化丢失。

## 部署与测试边界

先安全停止对应机器的视频号节点，确认进程退出，再覆盖本更新包中的 `视频号\common` 同名文件。不要覆盖/删除任务队列、凭据、`.state`、`runs` 或浏览器资料。之后使用原启动入口启动；已经退出的远端进程不会因本机代码修改自行恢复。

本机验收使用 E 盘临时目录、虚拟时钟和显式假的 MySQL 驱动，运行真实的入库封装器、入库程序及 PowerShell 工作节点入口，覆盖断网恢复、耗尽、人工停止、提交状态不明和禁止跳词。没有切断真实网络、写生产数据库、领取生产任务或操作生产浏览器。不将隔离测试通过等同于远端网络已经恢复。
